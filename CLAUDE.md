# Music practice site — notes for Claude

A personal music-learning website for guitar and piano (for the owner and friends, possibly wider later).
Plain static HTML/CSS/JS, no build step, hosted on GitHub Pages: https://rubensanders28.github.io/music/
(repo github.com/rubensanders28/music, branch `main`).

## Working with the owner
- Reply in English, plainly; explain in musician's terms, not code terms.
- **Commit only when asked** ("yes" / "commit" after a change is shown). The owner **pushes** themself in GitHub Desktop;
  you can't push (no credentials). After committing, say it's ahead of GitHub and needs a push.
- git isn't on PATH. Use: `C:\Users\rjbsa\AppData\Local\GitHubDesktop\app-3.6.10\resources\app\git\cmd\git.exe`
  (the version folder may change after GitHub Desktop updates).
- Usage matters: combine steps, avoid needless screenshots, read only the parts of big files you need
  (`songs.html` is ~2,400 lines). For small text/layout changes a quick error check is enough.

## Testing
- Local server: `.claude/serve.ps1` via `.claude/launch.json` ("site", port 8765). Start with the preview tool
  (`preview_start {name: "site"}`), never by hand. Opening the HTML as a file won't load the shared scripts.
- The built-in browser pane has the owner's own test data. **Before testing, snapshot localStorage; afterwards restore it
  and reload the page** (otherwise the page shows stale test data). Pattern used: save
  `Object.fromEntries(Object.keys(localStorage)...)` to `sessionStorage.__snap`, restore non-`sb-` keys, restoring
  `sync:` keys last so sync stamps stay as they were.
- `prompt()` doesn't work in the app's browser pane (Electron) or some phones: use on-page inputs instead. `confirm()` works.
- Don't load external scripts into pages from the test tool; test through the page's own code.

## Structure
Every page starts with `<script src="nav.js"></script><script src="sync.js"></script>` right after `<body>`.
- `nav.js` — the menu (add new pages to `PAGES`).
- `sync.js` — accounts and sync with Supabase (see below).
- `chord-data.js` — shared music data and drawing, loaded by most pages: `NOTES`, `FLATS`, `pretty(i)`, `OPEN`,
  `STRING_NAMES`, `TYPES` (chord types), `SHAPES` → `CHORDS` (all guitar shapes, generated by sliding shapes; moved
  shapes with a >3-fret stretch are skipped), `SLASH_CHORDS` (common slash chords; add new ones there) + `pianoSlashChord`,
  `MAJOR`/`MINOR`, `LETTERS`, `NATURAL`, `ACCIDENTAL`, `spellScale`, `SCALE_TYPES`, `ROOTS`, `spellNotes`,
  guitar sound (`audio`, `pluck`, `strum`), `drawChord`, `pianoChord`, `drawPianoChord`.
  **Its top-level names are global**: don't redeclare `pretty`, `SHAPES`, `LEFT`, `TOP`, `x`, `ROWS`, `el`, etc. in a page.
- `piano-sound.js` — `playPiano(midi, when)` (a const: can't be reassigned).
- `recent.js` — accuracy over the last 50 answers (`lastAnswers(key)`), `weak.js` — weak spots (`weakSpots(key)`),
  `midi.js` — Web MIDI keyboard input (`Midi`).

Pages: journey (My journey: milestones + practice calendar/timer), warmup, index (Piano trainer / note reading),
keyboard (scale & chord highlighter, MIDI), guitar (Fretboard trainer), chords (Chord trainer), ear (Ear trainer),
rhythm (Rhythm trainer), chord-library (shapes, formulas, slash chords, known/mastered marks), keys (Chords in a key),
songs (My songs), intervals, circle (Circle of fifths), scales (Scale shapes), caged (CAGED system), metronome (Tempo ladder).

## Data and sync
- Everything is in localStorage. `sync.js` patches `setItem/removeItem` to stamp changes and syncs every key except
  `sync:*` (device-only) and `sb-*` (Supabase session). Newest change wins **per key**, so keys written by two devices
  at once must be split (e.g. practice log: `practice:<YYYY-MM>:<deviceId>`, device id in `sync:device`).
- Supabase project URL and the **publishable** key are in `sync.js` (public by design; protected by RLS in
  `supabase-setup.sql`). Never put a secret/service_role key in the site. Don't create real accounts for the owner.
- Shared settings: `fretTrainerHand` ("left"/"right") = left-handed diagrams everywhere.
- `chordsKnown` = Chord library marks `{ guitar: { "<root>-<typeId>-<frets>": {s,d} }, piano: { "<root>-<typeId>": … } }`;
  slash chords use type id `slash<bassPc>` (G/B guitar: `7-slash11-x,2,0,0,3,3`).

## My songs (`songs.html`) — the most complex page
- `mySongs`: array of `{ id, title, artist, link, status, statusDates, opened, chords, sheet, transpose, capo }`.
  A chord is `{ root, type, bass? }` (bass only for slash chords).
- **One capo rule:** the chords you enter or import are the chords you play; `capo` is where the capo is, so they
  *sound* that much higher (sound, piano view, "sounds in" key). Capo never changes the chords shown; only `transpose`
  does. (An old `sheetCapo` field is converted on load by `convertOldCapo`.)
- Lyrics sheet: `sheet.sections[{ name, lines }]`; a line is `{ w: [words], c: { key: "Am" }, t? }` or a chords-only row
  `{ o: [...] }`. Chord keys: `"3"` start of word 3, `"3:2"` letter 2 of word 3, `"3+"` gap after word 3.
- Import: screenshot OCR with Tesseract.js (loaded from jsdelivr; English, or Hebrew = `heb+eng` plus a Hebrew-only
  re-read), LRCLIB lyrics search (lrclib.net, with line timings), or pasted text. Hebrew lines render right to left.

## Style conventions
- Each page has the same CSS colour tokens on `:root` with a `prefers-color-scheme: dark` block; mobile-friendly
  (no sideways page scroll; wide diagrams scroll inside their own box).
- Code comments explain *why*, in plain English, for a learner reading the code.
- Spell notes correctly for the key/chord (B♭ in F, the 3rd of A is C♯); use ♯/♭ in the UI.
- If an element uses `display: flex`, add `[hidden] { display: none !important; }` or `hidden` won't hide it.
